# سياسة أسماء المستخدمين في Yemen Motion

**الحالة:** Approved مبدئيًا للتنفيذ
**المرونة:** يسمح بتطوير التفاصيل الأمنية دون تغيير المبادئ المعتمدة

## Decision

يفصل النظام بين Display Name و`username`. الاسم الظاهر مرن ومهني، بينما
`username` معرف عام فريد وثابت نسبيًا يستخدم في الرابط والبحث والإشارة.

## Rationale

- يسمح بتغيير الهوية المهنية الظاهرة دون كسر الرابط العام.
- يمنع التباس حالة الأحرف والأسماء الرقمية وأسماء النظام.
- يحمي الأسماء القصيرة والرسمية من المضاربة والانتحال.
- يوازن بين حق المستخدم في التغيير واستقرار الروابط.

## Scope

تطبق السياسة على إنشاء `username` والتحقق من إتاحته وتغييره وتسجيل الدخول
والحجز والتعطيل والحذف والتدخلات الإدارية.

## Approved Behavior

### 1. Display Name

- منفصل عن `username`.
- يدعم العربية والإنجليزية والمسافات.
- يمكن تغييره دون تغيير الرابط العام.
- ليس بالضرورة الاسم القانوني.

### 2. Username

`username` معرف عام فريد يستخدم في الرابط والبحث والإشارة.

| القاعدة | السلوك المعتمد |
|---|---|
| الأحرف المسموحة | `a-z` و`0-9` و`-` و`_` |
| شرط الحروف | حرف لاتيني واحد على الأقل |
| الأرقام فقط | ممنوعة |
| البداية والنهاية | لا يبدأ أونتهي بـ`-` أو`_` |
| الفواصل | لا يسمح بفاصلين متتاليين |
| التخزين | Canonical Lowercase |
| الإدخال الكبير | يتحول تلقائيًا إلى lowercase |
| Uniqueness | غير حساسة لحالة الأحرف بسبب Canonical Lowercase |

لا يسمح بحسابين مثل `Motion` و`motion`.

### 3. الأطوال وPrivileged/Special Names

- طول الحساب العادي: **4–24** حرفًا.
- `username` من حرف واحد ممنوع.
- الأسماء من حرفين أوثلاثة هي Privileged/Special Names.

Privileged Names:

- لا تنشأ من التسجيل العام.
- لا يختارها المستخدم مباشرة.
- تنشئها أوتخصصها الإدارة فقط.
- تحتاج صلاحية مناسبة وسببًا وسجل تدقيق.
- لا تباع ولا تنقل بين الحسابات دون قرار إداري موثق.
- تخضع لحماية أقوى عند الحذف أوالتعطيل.

### 4. الرابط العام

المسار الرسمي:

`/designers/{username}`

يمكن لاحقًا توفير `/@{username}` بوصفه Alias يعيد التوجيه، وليس المسار
المرجعي الأول. تغيير Display Name لا يغير الرابط.

### 5. فحص الإتاحة والحجز

- يقدم فحص إتاحة فوري أثناء الكتابة.
- الرسالة الأولية ليست حجزًا نهائيًا.
- يكون الحجز النهائي Atomic داخل معاملة.
- Unique Index إلزامي.
- يطبق Rate Limit على فحص الإتاحة.
- لا يكشف النظام هوية صاحب `username` المحجوز.
- يمكن تقديم اقتراحات بديلة مفهومة.

هذه متطلبات سلوكية وأمنية، وليست Schema نهائيًا لقاعدة البيانات.

### 6. Reserved Names

يوجد سجل مركزي قابل للإدارة يشمل أسماء النظام والإدارة والدعم والأمان
والفوترة والطلبات والمسارات الرسمية.

القائمة الأساسية:

| | | | |
|---|---|---|---|
| `admin` | `administrator` | `support` | `help` |
| `api` | `login` | `register` | `settings` |
| `account` | `designer` | `designers` | `client` |
| `clients` | `staff` | `system` | `security` |
| `billing` | `payments` | `orders` | `requests` |
| `yemenmotion` | `yemen-motion` | `official` | `verified` |

يشمل السجل أيضًا الكلمات المسيئة والانتحال وأسماء العلامة والمسارات
المستقبلية. يستطيع Super Admin الحجز أوفك الحجز أوالتخصيص لحساب رسمي،
مع سبب وتدقيق.

### 7. تغيير Username

- يسمح بالتغيير مرتين خلال 90 يومًا.
- يحتاج تحققًا أمنيًا مناسبًا.
- يعرض للمستخدم أثر تغيير الرابط.
- يحمى `username` القديم 180 يومًا.
- يعيد الرابط القديم التوجيه خلال مدة الحماية.
- لا يحصل حساب آخر على الاسم أثناء الحماية.
- قد تحتفظ الحسابات الرسمية والخاصة بالاسم مدة أطول.
- يدقق كل تغيير.

### 8. الحذف والتعطيل

| الحدث | مصير الاسم |
|---|---|
| التعطيل المؤقت | يبقى محجوزًا |
| الإيقاف الإداري | يبقى محجوزًا |
| الحذف | يدخل Quarantine سنة واحدة على الأقل |
| اسم رسمي أوموثق | لا يتحرر آليًا |
| Privileged Name | لا يعود تلقائيًا للتسجيل العام |

لا يحرر `username` بسبب قلة نشاط الحساب. التحرير بعد الحجر يحتاج سياسة
ومراجعة.

### 9. Anti-Squatting

- الأسبقية للحجز الصحيح.
- تمنع المضاربة والبيع والانتحال.
- نزاعات العلامات التجارية لها مسار إداري منفصل.
- تستطيع الإدارة فرض إعادة تسمية عند الضرورة مع السبب والتدقيق.
- تخضع Privileged Names لرقابة أشد.

### 10. تسجيل الدخول

اسم حقل تسجيل الدخول المرئي:

**اسم المستخدم أو البريد الإلكتروني**

يستخدم الحقل الموحد مع كلمة المرور، ويقبل `username` أوemail.

- يحول `username` المدخل إلى lowercase قبل المطابقة.
- يعالج البريد وفق التطبيع والسياسة الأمنية المناسبة.
- رسالة الفشل العامة لا تكشف أي قيمة كانت غير صحيحة، ولا تكشف هل
  `username` أوemail موجود.
- تغيير `username` لا يمنع الدخول بالبريد.

رسالة الفشل العامة:

> تعذر تسجيل الدخول. تحقق من اسم المستخدم أوالبريد الإلكتروني وكلمة المرور.

تسجيل الدخول بالهاتف مؤجل إلى محطة إدارة الحساب والتحقق من الهاتف. اسم
المستخدم عام؛ يعتمد أمان الحساب على كلمة المرور وRate Limiting والتحقق
الثنائي مستقبلًا.

### 11. Super Admin

يستطيع Super Admin التخصيص وإعادة التسمية والحجز في الحالات الضرورية.
تحتاج التدخلات الحساسة سببًا مكتوبًا، وتسجل:

- القيمة السابقة والجديدة.
- المنفذ.
- الوقت.
- السبب.

لا يرى Super Admin كلمات المرور الحالية أوالأسرار، ولا يتجاوز Audit Log.

تظهر هذه السياسة في تجربة الملف المحددة في
[`DESIGNER_PROFILES_UX_CONTRACT.md`](DESIGNER_PROFILES_UX_CONTRACT.md)،
وتستخدم مكونات الإدخال والتغذية الراجعة في
[`PUBLIC_COMPONENT_CONTRACTS.md`](PUBLIC_COMPONENT_CONTRACTS.md).

## Rejected Alternatives

- ربط Display Name بالرابط العام.
- السماح باسم رقمي بالكامل أوبفواصل طرفية أومتتالية.
- اعتبار حالة الأحرف أساسًا لإنشاء حسابين مختلفين.
- إتاحة الأسماء من حرفين أوثلاثة في التسجيل العام.
- تحرير الاسم عند التعطيل أوالإيقاف أوقلة النشاط.
- كشف وجود البريد أو`username` في رسالة فشل تسجيل الدخول.
- تجاوز Audit Log عند تدخل Super Admin.

## Deferred Decisions

- سياسة تسجيل الدخول بالهاتف.
- التحقق الثنائي.
- استعادة الحساب بالهاتف.
- نزاعات العلامات التجارية التفصيلية.
- شروط منح Privileged Names تجاريًا أوتوثيقيًا.
- واجهة إدارة سجل Reserved Names.

## Implementation Notes

يسمح بتطوير Rate Limiting والتطبيع والتحقق الأمني بما يزيد الحماية دون
تغيير المبادئ أعلاه. لا تتضمن الوثيقة Migration أوSchema نهائيًا.

أي تغيير لاحق في الصيغة أوالأطوال أوالحماية أوصلاحيات الإدارة يحتاج قرارًا
صريحًا موثقًا.
