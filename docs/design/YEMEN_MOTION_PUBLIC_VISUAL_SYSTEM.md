# النظام البصري الخارجي لمنصة Yemen Motion

**الحالة:** Approved

**النوع:** قرار ملزم
**النطاق المرجعي:** الواجهات العامة ومساحات المصمم والعميل

## Decision

تعتمد منصة Yemen Motion نظامًا بصريًا خارجيًا مستقلًا للزوار والمصممين
والعملاء. هويته Modern وBold وProfessional وCreative، وتقوم على الأبيض
والفحمي وأحمر العلامة.

هذا النظام منفصل تمامًا عن النظام الإداري الموثق في
[`YM-ADMIN-VISUAL-SYSTEM-001`](../ym-sdd/specs/YM-ADMIN-VISUAL-SYSTEM-001.md)
و[`YM-ADMIN-VISUAL-RULES`](../ym-sdd/standards/YM-ADMIN-VISUAL-RULES.md).
يمنع نقل البنفسجي الإداري أومعالجة الزجاج الإداري إلى الواجهات الخارجية.
يمكن مشاركة المنطق التقني، لكن لا يشارك الشكل أوالعقد البصري.

## Rationale

- تحتاج الواجهة الخارجية إلى هوية علامة واضحة ومهنية تبرز أعمال المصممين.
- تحتاج المساحات التشغيلية إلى هدوء ووضوح أعلى من صفحات التسويق.
- يمنع الفصل البصري التباس واجهات الجمهور مع أدوات Admin وStaff الداخلية.
- يحافظ النظام الدلالي على فصل الهوية عن النجاح والتحذير والخطر.

## Scope

يشمل القرار:

- الصفحات العامة والاستكشاف والأعمال والخدمات.
- ملفات المصممين والعملاء.
- مساحات المصمم والعميل التشغيلية.
- الطلبات والرسائل والإشعارات عند بناء محطاتها مستقبلًا.

لا يشمل صفحات Admin وStaff الداخلية.

## Approved Behavior

### 1. الهوية والألوان

صفحات التسويق يمكن أن تكون أقوى وأغمق. الصفحات التشغيلية فاتحة وهادئة.
الفحمي مخصص للـHero والهوية والمناطق البارزة، وليس خلفية افتراضية لكل
المساحات التشغيلية. الأحمر للإجراء الأساسي والحالة النشطة ولمسات الهوية،
وليس لكل عنوان أوحد.

| الدور | القيمة | الاستخدام |
|---|---:|---|
| Brand Red | `#E21D1D` | الهوية والإجراء الأساسي |
| Primary Dark | `#111111` | Hero والهوية والمناطق البارزة |
| Page Surface | `#FCFCFC` | خلفية الصفحات التشغيلية |
| Card Surface | `#FFFFFF` | البطاقات والأسطح المرتفعة |
| Primary Text | `#151515` | النص الأساسي |
| Brand Red Text | `#C91414` | النص الأحمر الصغير عند الحاجة إلى تباين أعلى |
| Danger | `#B42318` | الأخطاء والإجراءات التدميرية فقط |
| Success | `#16803D` | النجاح |
| Warning | `#B45309` | التحذير |
| Info | `#2563EB` | المعلومات |

يفصل Brand Red عن Danger Red في الاسم والدلالة والاستخدام. لا يعتمد أي معنى
على اللون وحده.

### 2. Typography

- العربية: `IBM Plex Sans Arabic`.
- اللاتينية: `IBM Plex Sans`.
- البدائل: `Inter` ثم `system-ui`.
- الأوزان الأساسية: `400` و`500` و`600` و`700` و`800`.
- قياس Body الأساسي: `16px`.
- لا يقل نص Input على الهاتف عن `16px`.
- يدعم النظام RTL وLTR والنصوص المختلطة دون تغيير المعنى أوالترتيب.

### 3. Spacing and Geometry

نظام المسافات مبني على `4px`. القيم الأساسية:

`4، 8، 12، 16، 20، 24، 32، 40، 48، 64، 80، 96، 128`.

| الخاصية | العقد |
|---|---|
| Standard max-width | `1280px` |
| Exceptional wide max-width | `1440px` |
| Reading width | `68–72ch` |
| Desktop grid | 12 columns |
| Tablet grid | 8 columns |
| Mobile grid | 4 columns |
| Reference breakpoints | `640، 768، 1024، 1280، 1536px` |
| Radius scale | من `6px` إلى `32px` مع pill |
| Minimum touch target | `44×44px` |
| Standard field height | `48px` |
| Typical primary button | `48px` |

الهاتف ليس نسخة مصغرة من Desktop؛ تعاد فيه الأولويات والتدفق والتفاعل.

### 4. Page Shells

| Shell | الاستخدام |
|---|---|
| Public Shell | الزوار والتسويق والاستكشاف والملفات العامة |
| Workspace Shell | أعمال المصمم والعميل التشغيلية |
| Focused Shell | التسجيل والاستعادة والتدفقات محدودة التركيز |

- يستخدم Public Header للزوار.
- يستخدم Workspace Sidebar/Header للمصمم والعميل.
- يمكن استخدام Drawer أوBottom Navigation على الهاتف بحسب عدد الوجهات.
- يكون Public Footer فحميًا.
- تبقى الإدارة الخارجية منفصلة بصريًا عن Admin.

### 5. Cards

الأنماط المعتمدة: Standard Card وDark Identity Card وWork Card وDesigner
Card وStatistics Card وAction Card. تستخدم حدودًا خفيفة وظلالًا منضبطة.
يحظر Glassmorphism الواسع، ولا يظهر Hover إلا على العنصر التفاعلي. يمنع
التداخل المفرط لنمط Card داخل Card.

تفاصيل العقود في
[`PUBLIC_COMPONENT_CONTRACTS.md`](PUBLIC_COMPONENT_CONTRACTS.md).

### 6. Interaction

- Primary أحمر، وSecondary أبيض أوفحمي بحد.
- Danger مستقل لونيًا ودلاليًا عن Brand Red.
- يبقى Disabled ظاهرًا، ويشرح سبب التعطيل عند الحاجة.
- لا يغير Loading عرض الزر.
- يكون `focus-visible` واضحًا.
- لا تعتمد وظيفة على Hover وحده.
- لا يستخدم Placeholder بدل Label.

### 7. Feedback and Motion

ترتيب التغذية الراجعة: Inline ثم Banner ثم Toast ثم Blocking Overlay.
يستخدم Modal للقرار أوالتأكيد فقط، وDrawer للسياق الإضافي، وBottom Sheet
للهاتف. يجب أن يشبه Skeleton المحتوى النهائي.

تحفظ مدخلات المستخدم عند فشل الشبكة، ولا تعرض الأخطاء التقنية للمستخدم.
تتراوح الحركة بين `120–320ms` بحسب النوع، مع احترام
`prefers-reduced-motion`.

### 8. Media

- غلاف العمل الافتراضي `16:9`، مع دعم `1:1` و`4:5` و`3:4` و`21:9`.
- الصورة الشخصية `1:1`.
- غلاف المصمم عريض ويدعم Focal Point.
- لا يبدأ الفيديو بصوت تلقائي، وله Poster واضح.
- يدعم الفيديو الأفقي والعمودي.
- تستخدم Lazy Loading وResponsive Images و`srcset`.
- تفضل AVIF وWebP مع fallback.
- تستخدم أصول العلامة الرسمية بصيغة SVG وفق
  [`BRAND_ASSETS_REGISTER.md`](BRAND_ASSETS_REGISTER.md).
- يخضع SVG المرفوع من المستخدم للفحص الأمني.
- Watermark اختياري وسياقي فقط.
- لا يعطل Right-click بوصفه حماية.
- لا تفرض ألوان المنصة أوFilters على أعمال المصممين.

### 9. Accessibility and Localization

الهدف هو **WCAG 2.2 AA**. يشمل العقد:

- Semantic HTML وKeyboard Navigation وSkip Link.
- ترتيب Focus منطقي وFocus ظاهر واستعادة صحيحة للتركيز.
- دعم Zoom حتى `200%`.
- تباين مناسب وعدم الاعتماد على اللون وحده.
- CSS Logical Properties.
- العربية RTL والإنجليزية LTR.
- `dir="auto"` و`bdi` للمحتوى المختلط.
- عدم عكس الشعار في RTL.
- `Intl` للأرقام والتواريخ والعملات وقواعد جمع صحيحة.
- أهداف لمس مناسبة.

الوصول جزء من تعريف المكون وقبول التنفيذ، وليس مرحلة لاحقة.

### 10. Data Presentation

- Grid Cards للأعمال والمصممين في السياقات العامة.
- List أوTable للبيانات التشغيلية.
- بحث هجين مع debounce بين `300–400ms` ودعم Enter.
- تحفظ عبارة البحث والفلاتر في URL.
- تمثل الفلاتر النشطة بواسطة Chips.
- تنتقل الفلاتر على الهاتف إلى Drawer أوBottom Sheet.
- يستخدم Pagination المرقم للاستكشاف والبحث.
- يستخدم Load More لقوائم تشغيلية محددة فقط.
- يمنع Infinite Scroll المفتوح في الصفحات الأساسية.
- يسمح بالفرز القابل للتفسير فقط.
- يستخدم Table عند الحاجة إلى مقارنة أعمدة فعلية، ولا يضغط إلى أعمدة غير
  مقروءة على الهاتف.

### 11. Content Tone

اللغة بسيطة ومباشرة ومهنية، وتوضح حق المستخدم والإجراء المطلوب والمانع.
لا تلوم المستخدم ولا تقدم وعودًا غير قابلة للإثبات. يعتمد قاموس موحد
يفصل بين:

- الحساب النشط.
- الملف المنشور.
- اكتمال الملف.
- التوثيق.
- التميز.
- التوفر.

### 12. Privacy and Trust

- البيانات الحساسة Private by default.
- نشر الملف العام Explicit.
- لا يظهر البريد أوالهاتف للعامة افتراضيًا.
- بيانات العميل أكثر خصوصية.
- الرسائل والطلبات والمرفقات خاصة بأطرافها والإدارة المخولة.
- التوثيق لا يعني ضمان الجودة، والتميز لا يعني التوثيق.
- يجب توفير عقد بصري واضح للإبلاغ والمحتوى المخفي وقيد المراجعة.

راجع عقد الملف والخصوصية في
[`DESIGNER_PROFILES_UX_CONTRACT.md`](DESIGNER_PROFILES_UX_CONTRACT.md)،
وسياسة المعرف العام في [`USERNAME_POLICY.md`](USERNAME_POLICY.md).

### 13. Design Tokens

تتكون البنية من:

1. Primitive Tokens للقيم الخام.
2. Semantic Tokens للأدوار والسياقات.
3. CSS Variables مرتبطة بـTailwind.

يمنع تكرار Hex أوالقيم العشوائية داخل المكونات. يسمح أثناء التنفيذ
بتعديلات ثانوية تحافظ على الهوية؛ ويوثق أي نمط متكرر في Tokens بدل نسخه.

### 14. تطبيق الهاتف المستقل

تطبيق الهاتف مشروع مستقل يبدأ بعد إطلاق المنصة. يشارك ألوان العلامة والخطوط
والأيقونات والحالات وDesign Tokens، لكنه لا يلتزم بتخطيط Web نفسه.

## Rejected Alternatives

- نقل البنفسجي أوGlassmorphism الإداري إلى النظام الخارجي.
- استخدام Brand Red بوصفه Danger Red.
- جعل الأحمر لون كل العناوين والحدود.
- تحويل الهاتف إلى نسخة مكدسة من Desktop.
- حماية الوسائط بتعطيل Right-click أوفرض Watermark دائم.
- استخدام Infinite Scroll المفتوح في الصفحات الأساسية.

## Deferred Decisions

- تفاصيل واجهات الرسائل والإشعارات والطلبات حتى توثيق محطاتها.
- تخطيط تطبيق الهاتف الأصلي، مع بقاء عناصر الهوية المشتركة ملزمة.

## Implementation Notes

### Acceptance

يجب أن تغطي مراجعة أي تنفيذ لاحق:

- Desktop وTablet وMobile Web.
- Arabic RTL، وEnglish LTR عند توفر النصوص.
- Keyboard وFocus وZoom `200%`.
- Loading وEmpty وError.
- Contrast وWCAG 2.2 AA.
- مراجعة بصرية من مالك المشروع قبل Commit.

لا ينفذ Commit لواجهة قبل الاعتماد البصري. أي تغيير لاحق في هذا العقد يحتاج
قرارًا صريحًا موثقًا.
