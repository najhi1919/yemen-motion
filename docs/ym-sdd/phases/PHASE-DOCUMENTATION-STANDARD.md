# معيار توثيق المراحل

## الغرض

توجد طبقة `phases` لربط خطة المشروع طويلة المدى بالتنفيذ اليومي. تحتفظ كل مرحلة بصورة تشغيلية واحدة لخطة النطاق، الحالة الحالية، القرارات المتغيرة، المحطات، الأدلة، وما يلزم قبل الإغلاق. لا تحل هذه الطبقة محل المواصفات أوالمهام أوالقرارات المعمارية.

## ترتيب مصادر الحقيقة

1. `PROJECT_MAP.md`: المرجع الأعلى لخطة المشروع وترتيب المراحل والاعتماديات.
2. `docs/ym-sdd/phases/{phase}/`: المرجع التشغيلي التفصيلي للمرحلة وحالتها وقراراتها وتقدمها.
3. `specs/`: العقود الفنية والوظيفية التفصيلية قبل التنفيذ.
4. `tasks/`: مهام التنفيذ وتقارير إغلاق المحطات.
5. `adr/`: القرارات المعمارية طويلة الأثر.
6. `Git commits + Tests + Build results`: أدلة التنفيذ والإغلاق الفعلية.

عند التعارض لا يُعدّل التاريخ بصمت. يُضاف قرار جديد بحالة واضحة ويذكر `Supersedes` القرار السابق. لا يُنسب تنفيذ أوCommit مثبت إلى محطة غير موثقة دون دليل، ولا يعد وصف الخطة دليلًا على التنفيذ، ولا يعد وجود الكود وحده دليلًا على إغلاق المحطة.

## الحالات المعتمدة

`proposed`، `under-discussion`، `approved`، `planned`، `in-progress`، `blocked`، `technically-verified`، `visually-approved`، `closed`، `superseded`، `cancelled`.

## الهيكل الإلزامي

```text
phases/{phase}/
├── README.md
├── PHASE-PLAN.md
├── CURRENT-STATE.md
├── DECISIONS.md
├── PROGRESS.md
├── ACCEPTANCE-CRITERIA.md
├── PHASE-CLOSURE.md
└── stations/
    ├── README.md
    └── {STATION-ID}.md
```

وظائف الملفات:

| الملف | الوظيفة |
|---|---|
| `README.md` | فهرس المرحلة وبياناتها الأساسية. |
| `PHASE-PLAN.md` | الهدف، النطاق، التقسيم، الاعتماديات، والترتيب المعتمد. |
| `CURRENT-STATE.md` | مصفوفة ما هو منفذ، جزئي، مخطط، أوخارج النطاق. |
| `DECISIONS.md` | قرارات مرقمة وسجل الاستبدال دون حذف التاريخ. |
| `PROGRESS.md` | سجل زمني `Append-only` للمحطات والأدلة. |
| `ACCEPTANCE-CRITERIA.md` | معايير قابلة للتحقق وحالتها ودليلها. |
| `PHASE-CLOSURE.md` | بوابة الإغلاق والأدلة النهائية؛ لا تُكتب كإغلاق مبكر. |
| `stations/` | ملفات المحطات المنفذة أوالمخططة داخل المرحلة. |

## دورة التوثيق

- تُنشأ المرحلة عند بدء مناقشة نطاقها أوعند الحاجة إلى إعادة بناء مرجع تشغيلي لمرحلة قائمة.
- يُنشأ ملف محطة عند اعتماد معرفها ونطاقها المبدئي، قبل التنفيذ إن أمكن.
- تُحدّث `DECISIONS.md` عند اعتماد قرار أوتغييره. القرار البديل يضاف ولا يمحو السابق.
- تُحدّث `PROGRESS.md` عند فتح محطة، تغير حالتها، ظهور عائق، اكتمال تحقق تقني، اعتماد بصري، Commit، Push، نتيجة CI، أوإغلاق.
- تُحدّث `CURRENT-STATE.md` ومعايير القبول بعد الأدلة، لا بناءً على النية.
- لا تصبح `PHASE-CLOSURE.md` بحالة `CLOSED` إلا بعد تحقق كل المعايير الإلزامية، اكتمال المحطات، وجود أدلة Commit واختبارات وBuild ومراجعة بصرية مطلوبة، واعتماد المستخدم.

## عقد ملف المحطة

يحتوي كل ملف محطة على: Station ID، الاسم، الحالة، المرحلة، الاعتماديات، نقطة الأساس، تاريخ الفتح، تاريخ الإغلاق عند الإغلاق، الهدف، `In Scope`، `Out of Scope`، القرارات المعتمدة، الملفات المنفذة، العقود والواجهات، اختبارات التحقق، المراجعة البصرية، Commit، Push، CI، المشاكل والتصحيحات، الحدود المتبقية، المحطة التالية، وسجل زمني `Append-only`.

## أدلة التنفيذ والإغلاق

- يسجل Commit بالـSHA الكامل مع وصف ما يثبته، ولا يستخدم Commit متوقع.
- تسجل الاختبارات بالأمر أوالنطاق، العدد، assertions، النتيجة، وتاريخ التحقق إن توفر.
- يسجل Build بنوعه ونتيجته؛ عدم تشغيله يكتب صراحة.
- تسجل المراجعة البصرية بالأحجام والحالات التي عُرضت ومن اعتمدها؛ نجاح Build لا يساوي اعتمادًا بصريًا.
- يسجل Push والفرع والوجهة إذا ثبتا.
- تسجل نتيجة CI كما ظهرت. الاستعلام الفوري بلا نتيجة لا يُحوّل إلى نجاح أوفشل، ويذكر إن لم يحدث polling.

## التاريخ غير الموثق وتغير القرارات

تُراجع المحطات القديمة عبر الملفات و`Git`. تسجل القدرات والـCommits المثبتة فقط. إذا لم يثبت Station ID، تستخدم العبارة:

`Historical implementation — original station ID not recoverable from repository evidence.`

عند تغير قرار، يضاف قرار جديد يحدد السبب والأثر و`Supersedes`. تبقى أحداث التقدم والقرارات السابقة للرجوع والمساءلة.

## ضوابط الإغلاق والسلامة

- لا تعلن مرحلة مكتملة بناءً على نسبة تقدم جزئية أوإغلاق Workspace داخلي فقط.
- لا يعد إعداد مخزن تطبيقًا عامًا ما لم يوجد مستهلك عام مثبت.
- لا يُعدّل `PROJECT_MAP.md` ضمن محطات التنفيذ؛ يتطلب ذلك مهمة توثيق مستقلة ومصرحًا بها.
- تستخدم الوثائق Latin digits `0-9` فقط.
- لا توضع أسرار أوTokens أوبيانات مستخدمين حساسة أوبيانات اعتماد داخل الوثائق.
